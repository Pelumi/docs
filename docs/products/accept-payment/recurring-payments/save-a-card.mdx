**Step 1 of 5.** Before you can charge a card later, the customer has to pay with it once through Nomba Checkout.

## Why a first payment is needed

The first payment does two things:

1. It proves that the card is valid and can be charged.
2. The customer approves the payment with their bank. After that, you can charge the card later without the customer re-entering their card details.

## Create the checkout order

Create a checkout order as usual, and add `"tokenizeCard": true` to the request.

```bash
curl --request POST \
  --url https://api.nomba.com/v1/checkout/order \
  --header 'Authorization: Bearer <access_token>' \
  --header 'Content-Type: application/json' \
  --header 'accountId: <accountId>' \
  --data '{
    "order": {
      "orderReference": "sub-2026-10-0001",
      "customerId": "cus_48213",
      "customerEmail": "ada@example.com",
      "amount": "5000.00",
      "currency": "NGN",
      "callbackUrl": "https://example.com/payments/callback",
      "allowedPaymentMethods": ["Card"]
    },
    "tokenizeCard": true
  }'
```

<Warning>
  `tokenizeCard` goes at the **top level** of the request body, next to `order`. Nomba ignores it if you put it inside `order`, and the card isn't saved.
</Warning>

These fields matter for saving a card. For the full list, see [Create a checkout order](/docs/products/accept-payment/create-checkout-order).

| Field | Required | Description |
|---|---|---|
| `tokenizeCard` | Yes, for this flow | Set it to `true` to save the card when the payment succeeds. |
| `order.customerEmail` | Yes | The customer's email address. The card is saved against this email, and every later charge must use the same one. |
| `order.customerId` | Recommended | Your own ID for the customer. Nomba returns it in the webhook, so you can match the token to the customer in your system. |
| `order.orderReference` | Recommended | Your unique reference for this order. Nomba generates one if you leave it out. |
| `order.allowedPaymentMethods` | Recommended | Set it to `["Card"]`. Only a card payment can be saved, so if the customer pays by transfer or USSD, you won't get a token. |
| `order.amount`, `order.currency` | Yes | The amount and currency of the first payment. |

The response contains the `checkoutLink`:

```json
{
  "code": "00",
  "description": "Success",
  "data": {
    "checkoutLink": "https://checkout.nomba.com/pay/b6a3c0f2-6d2e-4c1a-9a41-3f2b7d0c9e15",
    "orderReference": "b6a3c0f2-6d2e-4c1a-9a41-3f2b7d0c9e15"
  }
}
```

<Note>
  `data.orderReference` in the response is Nomba's order ID, not the reference you sent. The webhook returns it as `order.orderId`. Keep your own reference too.
</Note>

## Take the first payment

Choose how the customer pays. Either way, Nomba saves the card when the payment succeeds.

<Tabs>
  <Tab title="Nomba checkout page">
    Redirect the customer to the `checkoutLink`, or open it in a web view in your app. The customer enters their card details and completes any checks their bank asks for, such as an OTP. You don't need to make any more API calls.
  </Tab>
  <Tab title="Your own page (API)">
    Collect the card details on your own page, then send them to Nomba with the `orderReference` from the response above. You need to be PCI DSS compliant to handle card details. For details such as card encryption and 3D Secure, see [Initialize charge](/docs/products/accept-payment/server-to-server).

    **1. Submit the card details**

    ```bash
    curl --request POST \
      --url https://api.nomba.com/v1/checkout/checkout-card-detail \
      --header 'Content-Type: application/json' \
      --data '{
        "cardDetails": "{\"cardNumber\": \"5061000000000000\", \"cardExpiryMonth\": 9, \"cardExpiryYear\": 2031, \"cardCVV\": 123, \"cardPin\": 1234}",
        "key": "",
        "orderReference": "b6a3c0f2-6d2e-4c1a-9a41-3f2b7d0c9e15",
        "deviceInformation": {
          "httpBrowserLanguage": "en-GB",
          "httpBrowserJavaEnabled": "true",
          "httpBrowserJavaScriptEnabled": "true",
          "httpBrowserColorDepth": "30",
          "httpBrowserScreenHeight": "900",
          "httpBrowserScreenWidth": "1500",
          "httpBrowserTimeDifference": "-60",
          "userAgentBrowserValue": "Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7)",
          "deviceChannel": "Browser"
        }
      }'
    ```

    | Field | Description |
    |---|---|
    | `cardDetails` | The card details as a JSON string: `cardNumber`, `cardExpiryMonth`, `cardExpiryYear`, `cardCVV` and `cardPin`. |
    | `key` | The encryption key if you encrypt `cardDetails`, otherwise an empty string. |
    | `orderReference` | `data.orderReference` from the create-order response, which is Nomba's order ID. |
    | `deviceInformation` | Details of the customer's browser or device. |

    The card is saved because you set `tokenizeCard: true` on the order. You don't need to send `saveCard`. On its own, `saveCard` saves the card to the customer's Nomba checkout, not to your account, so you can't charge it.

    When the bank asks for an OTP, `data.responseCode` is `T0`. Keep `data.transactionId` for the next call:

    ```json
    {
      "code": "00",
      "description": "card details submitted successfully",
      "status": true,
      "data": {
        "status": true,
        "message": "Kindly enter the OTP sent to **********9046",
        "responseCode": "T0",
        "transactionId": "0b572789-0770-44f8-b400-99164ef2712b",
        "secureAuthenticationData": null
      }
    }
    ```

    **2. Submit the OTP**

    Send the code the customer received, with the same `orderReference` and the `transactionId`. This call doesn't need an `Authorization` or `accountId` header.

    ```bash
    curl --request POST \
      --url https://api.nomba.com/v1/checkout/checkout-card-otp \
      --header 'Content-Type: application/json' \
      --data '{
        "otp": "975005",
        "orderReference": "b6a3c0f2-6d2e-4c1a-9a41-3f2b7d0c9e15",
        "transactionId": "0b572789-0770-44f8-b400-99164ef2712b"
      }'
    ```

    ```json
    {
      "code": "00",
      "description": "checkout otp processed successfully",
      "status": true,
      "data": {
        "status": true,
        "message": "SUCCESS"
      }
    }
    ```

    When `data.status` is `true`, the payment is complete and Nomba saves the card.
  </Tab>
</Tabs>

## Choose the amount for the first payment

If the first payment is the customer's first bill, such as the first month of a subscription, charge the real amount.

If you only need the payment to save the card, charge a small amount. Then [refund it](/docs/products/accept-payment/refund-checkout-order), or give the customer the same value in your app, such as wallet credit. Nomba doesn't set a minimum amount, but some banks decline very small card payments, so test the amount you plan to use.

<Tip>
  Set `tokenizeCard` only when you plan to charge the card again. Tell the customer you'll save their card and how you'll use it, and get their agreement before they pay.
</Tip>
