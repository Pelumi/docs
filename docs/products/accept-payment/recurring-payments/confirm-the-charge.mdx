**Step 5 of 5.** Always confirm a charge before you give the customer value, such as extending their subscription or crediting their wallet. Use both signals below.

## 1. Listen for the webhook

When a charge succeeds, Nomba sends a `payment_success` webhook to your webhook URL, with the same structure as the first payment. When a charge fails, Nomba sends `payment_failed`. Match the webhook to the charge by `data.order.orderReference`.

`data.order.isTokenizedCardPayment` is `"true"` (a string) for a charge on a saved card, and `"false"` for the first, card-saving payment. Use it to tell renewals apart from first payments in your webhook handler.

Nomba retries a webhook if your server doesn't respond with a `2xx` status, so the same event can arrive more than once. Give value only once for each `orderReference`.

## 2. Verify with the API

Look up the charge by your `orderReference`:

```bash
curl --request GET \
  --url 'https://api.nomba.com/v1/transactions/accounts/single?orderReference=sub-2026-11-0001' \
  --header 'Authorization: Bearer <access_token>' \
  --header 'accountId: <accountId>'
```

The charge succeeded only if **all** of these are true:

- `data.status` is `"SUCCESS"`.
- The `orderReference` in the response matches the one you charged.
- The amount matches the amount you charged.

If the status is anything else, don't give value yet. Check again later, or wait for the webhook.

For more ways to verify a transaction, see [Verify transactions](/docs/products/accept-payment/verify-transactions).
